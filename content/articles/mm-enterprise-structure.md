## 一句话理解

**企业结构（Enterprise Structure）是 SAP 系统的组织骨架**：它定义了"公司在系统里长什么样"——哪个是法人实体（公司代码）、哪里生产/收货（工厂）、货放在哪个库（库存地点）、谁负责买（采购组织/采购组）。所有 MM 主数据和业务单据都挂在这些组织单元上。

::: tip
实战提示：画图是理解企业结构的最好方法。拿一张白纸，从上到下画出 Client → 公司代码 → 工厂 → 库存地点，旁边再画采购组织 → 采购组，然后把物料主数据、供应商主数据的"组织级别"标注上去，结构关系立刻清晰。
:::

## MM 核心组织单元

| 组织单元 | 英文 | 说明 | 示例 |
|----------|------|------|------|
| 集团 | Client | 系统最高层级，数据物理隔离单位 | 800 |
| 公司代码 | Company Code | 独立核算的法人实体，对外报税、出财务报表 | CN01（中国公司） |
| 工厂 | Plant | 生产、收货、计划、库存管理的核心组织单元 | 1000（上海工厂） |
| 库存地点 | Storage Location | 工厂下的细分仓库，库存数量管理到这一层 | 0001（原材料库） |
| 采购组织 | Purchasing Organization | 负责采购的组织，可跨公司代码采购 | CNPO（中国采购组织） |
| 采购组 | Purchasing Group | 采购员/采购小组，不是一个组织层级，是"人"的分组 | 001（张三组） |

## 层级与分配关系

```flow
Client（集团）| 一个系统 / 一套主数据基础
↓
Company Code（公司代码）| 法人实体，财务核算单位
↓
Plant（工厂）| 归属一个公司代码，物流核心
↓
Storage Location（库存地点）| 归属一个工厂，库存数量层
```

采购侧是另一条线：

```flow
Purchasing Organization（采购组织）| 可分配给一个或多个公司代码 / 工厂
↓
Purchasing Group（采购组）| 归属采购组织，是采购员分组
```

关键分配关系（配置在 SPRO → 企业结构中完成）：

| 分配 | 说明 |
|------|------|
| 工厂 → 公司代码 | 一个工厂只能属于一个公司代码 |
| 库存地点 → 工厂 | 一个库存地点只能属于一个工厂 |
| 采购组织 → 公司代码 | 决定采购组织能为哪些公司代码采购 |
| 采购组织 → 工厂 | 决定采购组织能为哪些工厂采购（参考性/标准采购组织） |
| 采购组 → 采购组织 | 采购员归属哪个采购组织 |

::: warning
常见坑：**采购组织和公司代码的分配决定了跨公司采购是否可行**。如果工厂 A 的采购订单想用采购组织 B 下，必须先在企业结构里把 B 分配给 A 所在的公司代码/工厂。很多"PO 保存报错"的根因其实是分配没做，而不是 PO 本身的问题。
:::

## 主数据的组织级别

这是新人最容易混淆的点：主数据的不同"视图"维护在不同组织层级。

| 主数据 | 组织级别 | 说明 |
|--------|----------|------|
| 物料主数据-基本视图 | Client | 全集团共用，如物料描述、基本计量单位 |
| 物料主数据-采购视图 | 工厂 | 每个工厂可不同，如采购组、计划交货时间 |
| 物料主数据-会计视图 | 工厂（+公司代码估价） | 移动平均价/标准价，按工厂或公司代码估价 |
| 供应商主数据-一般数据 | Client | 名称、地址、税号 |
| 供应商主数据-公司代码视图 | 公司代码 | 统驭科目、付款条件、付款方式 |
| 供应商主数据-采购组织视图 | 采购组织 | 采购组、计划交货时间、合作伙伴角色 |

::: tip
实战提示：用户报"物料/供应商找不到"时，先问一句：**"你在哪个组织级别下维护/查找的？"** 十有八九是组织级别不对——比如只在工厂 1000 扩展了采购视图，却在工厂 2000 下单。
:::

## 实战配置清单

```checklist
- [ ] 定义公司代码（含国家/货币/语言/会计科目表）
- [ ] 定义工厂
- [ ] 工厂分配给公司代码
- [ ] 定义库存地点并分配给工厂
- [ ] 定义采购组织（标准/参考）
- [ ] 采购组织分配给公司代码
- [ ] 采购组织分配给工厂
- [ ] 定义采购组并分配给采购组织
- [ ] 定义工厂的地址信息（用于单据打印）
```

## 常见问题

### Q：工厂和公司代码到底什么区别？
A：公司代码是**财务视角**的法人实体（对外报税、出报表）；工厂是**物流视角**的地点（收货、生产、库存）。一个公司代码可以下挂多个工厂，但一个工厂只能属于一个公司代码。MM 业务单据（PO、GR）主要在"工厂"层跑，自动记账时才落到公司代码。

### Q：采购组织可以跨公司代码采购吗？
A：可以，这正是采购组织设计的价值：集中采购。一个采购组织可以分配给多个公司代码，为它们统一采购。但要注意跨公司采购涉及公司间结算（Intercompany Billing），FI 侧需要配套配置。

### Q：S/4HANA 里企业结构有变化吗？
A：基本概念没有变化。主要是主数据层面：供应商/客户统一为 Business Partner，组织级别的维护逻辑延续 ECC。企业结构的配置路径仍在 SPRO。

## 实战经验

- 项目初期**企业结构蓝图一定要冻结得早**：公司代码、工厂清单一旦确定，后续主数据收集、权限、报表都依赖它。蓝图阶段反复改工厂清单是灾难之源。
- 工厂编码规则建议**见名知意**：如用城市/国家缩写+序号。见过太多项目用 1000、1001 这种纯数字，三年后没人记得哪个是哪个。
- 库存地点不要建得过细：库存地点是库存数量的管理层级，建 50 个库存地点意味着盘点、报表、权限都要乘以 50。按**物理仓库/管理责任**划分，而不是按货架。
