## 一句话理解

MRP Live 是 S/4HANA 里**基于 HANA 内存计算重写的 MRP**，事务代码 `MD01N`。它和经典 MRP 的计划逻辑（净需求计算、批量规则）基本一致，区别是**快了一个数量级**，并且把"读取数据"和"计划计算"都在 HANA 里完成。

::: tip
实战提示：跟计划员解释 MRP Live 别谈技术，谈体感——"以前 MRP 跑一夜，现在喝杯咖啡的功夫就出结果，一天可以跑好几次。"计划员立刻有动力学。
:::

## 经典 MRP vs MRP Live

| 维度 | 经典 MRP（MD01/MD02） | MRP Live（MD01N） |
|------|------------------------|-------------------|
| 计算位置 | 应用服务器逐行算 | HANA 数据库内并行算 |
| 速度 | 大数据量跑批以小时计 | 分钟级 |
| 运行频率 | 多为每天/每周一次 | 可一天多次，甚至按需 |
| 数据读取 | 读应用层表 | 直接读 HANA 视图 |
| 结果查看 | MD04/MD05 | 同样用 `MD04` 看（界面延续） |

## 为什么能这么快

1. **列式存储** —— MRP 要扫海量物料需求数据，列存只读需要的列，IO 大减。
2. **计算下沉** —— 净需求、批量计算在数据库内并行跑，不用来回搬数据。
3. **简化数据模型** —— 中间汇总环节减少，读数路径更短。

```flow
MD01N 启动 | 选择工厂、计划模式
↓
HANA 内计算 | 净需求 → 批量 → 计划订单/采购申请
↓
结果 | MD04 查看，计划订单转生产订单/采购订单
```

## 适用边界：不是所有场景都用 MRP Live

| 场景 | 建议 |
|------|------|
| 常规 MPS/MRP 计划 | MRP Live |
| 依赖经典 MRP 特有功能的场景 | 经典 MRP 仍可运行，先验证 |
| 长期模拟计划 | 看版本支持情况，先验证 |

::: note
注意：MRP Live 有功能边界清单，项目蓝图阶段要对照检查计划员在用的特殊功能是否被支持。别等上线了才发现某个用了十年的计划技巧跑不了。
:::

## 排错思路：MRP 结果不对先查什么

```checklist
- [ ] 物料主数据的 MRP 视图：MRP 类型、批量、计划策略对不对
- [ ] 需求有没有真正进来（销售订单/预测）
- [ ] 库存、已分配量（MD04 先看）
- [ ] 计划日历、工厂日历
- [ ] MD01N 的计划模式：重排还是增量
```

## 常见问题

### Q：MRP Live 的计划结果和经典 MRP 一样吗？
A：标准逻辑下结果一致。差异通常来自主数据或参数，不是算法变了。并行测试阶段建议两个都跑一遍对结果。

### Q：MD04 在 S/4HANA 里还有吗？
A：有。`MD04` 库存/需求清单继续可用，也是排错的第一入口。另外 Fiori 有对应的库存分析 App。

### Q：MRP 能跑多次，会不会打乱生产？
A：计划订单只是建议，不会自动变成生产订单/采购订单（除非配了自动转换）。多跑几次只影响建议，不影响执行，放心跑。

## 实战经验

- 上线前做 **MRP 并行测试**：同一份数据跑经典 MRP 和 MRP Live，对比计划订单差异，差异清单逐条解释，这是计划员信任新系统的关键。
- MD01N 的后台作业调度要和 Basis 确认好，HANA 内存不足时 MRP Live 会慢甚至报错，先谈 sizing。
- 计划员培训重点放"结果怎么看、建议怎么转"，而不是"MRP 原理"——他们比你懂原理，缺的是新事务代码的手感。
