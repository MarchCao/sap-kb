Purchase Requisition（采购申请）

采购申请 PR 是 P2P 流程的起点：谁来提、怎么审批、ME51N 实战操作，以及释放策略这个最常见的配置坑。

一句话理解

采购申请（Purchase Requisition，PR）是"内部的需求单"：需求部门告诉采购"我要买什么、买多少、什么时候要"。它不发给供应商，没有法律效力，但它是 P2P 流程的起点——后续的采购订单可以参照 PR 创建，实现需求到采购的追溯。

实战提示

实战提示：给业务讲 PR 的价值只说一句——"没有 PR 的 PO 就是无头采购"。PR 回答了"谁要的、为什么买"，审计和预算控制都靠它。很多企业的内控第一要求就是：PO 必须有 PR 依据。

PR 的来源

来源 说明
手工创建（ME51N） 需求部门手工提，如办公用品、维修备件
MRP 跑出 MRP 根据需求自动产生采购申请（BSART=NB 的计划申请）
生产订单/项目 生产、项目产生的相关需求
销售订单（第三方） 第三方销售流程产生的采购申请

PR 行项目的关键字段

字段 说明
物料编码 / 短文本 有编码用物料主数据，无编码可用纯文本描述（注意：文本 PR 无法做库存管理）
数量、计量单位 需求数量
交货日期 希望到货日期，会传递给 PO
工厂、库存地点 需求地点
科目分配类别（Acct Assignment） 核心字段：K=成本中心、A=资产、P=WBS 元素……决定费用归集对象
物料组 无编码物料的分类，用于审批和报表
固定供应商/期望供应商 可指定建议的供应商
审批状态 释放策略控制的审批流状态

科目分配类别速查

类别 含义 典型场景
K 成本中心 办公用品、耗材等费用性采购
A 资产 固定资产采购，收货后转固
P WBS 元素 项目用料
Q 项目库存（已较少用） —
空 库存采购 直接进库存，无科目分配
注意

常见坑：PR 的科目分配类别选错，后续 PO、收货、发票的记账全错。比如该进费用的选成了库存采购，收货时借的是库存科目，月末对账对不上。PR 提单培训时，科目分配是必须讲透的一节。

释放策略（审批流）

PR 的审批通过**释放策略（Release Strategy）**实现，这是 MM 采购最经典的配置之一：

1
创建 PR（未审批）状态：被冻结，不能转 PO
↓
2
释放策略判定按总金额 / 物料组 / 工厂等特征值确定审批链
↓
3
逐级释放主管
↓
4
经理
↓
5
总监（可多级）
↓
6
已释放可以参照创建 PO
配置点 说明
特征（Characteristics） 判定维度：如总金额、物料组、工厂、科目分配类别
分类（Class） 把特征组合成"类"挂到 PR 类型上
释放组/释放代码 审批节点：谁可以批哪一级
释放指示符 每级的状态含义（已释放/被冻结）
释放策略 特征值组合 → 审批链的映射
实战提示

实战提示：排错"PR 审批流没触发"按这个顺序查：① PR 类型是否挂了分类；② 特征值（如金额）是否落在某个策略区间；③ 用户是否有释放代码的权限；④ 释放指示符配置。90% 的问题出在前两项。

实战操作要点

  • ME51N 创建：选凭证类型（NB=标准）→ 维护行项目 → 检查科目分配 → 保存。注意屏幕左下角的"处理状态"。
  • ME52N 修改：已释放的 PR 修改关键字段（数量、金额超限）会重置审批，需要重新走释放——这是标准行为，不是 bug。
  • ME53N 显示：查看审批状态、历史。
  • PR 转 PO：在 ME21N 中"参照采购申请"创建，或用 ME59N 自动生成 PO。

常见问题

Q：PR 可以直接发给供应商吗？

A：不可以。PR 是内部单据，没有对外法律效力。对外的是采购订单（PO）。如果业务说"我们直接拿 PR 给供应商下单"，那是流程不合规，需要纠正。

Q：MRP 跑出的 PR 和手工 PR 有区别吗？

A：有。MRP 产生的 PR 自带需求来源（相关需求、独立需求），转 PO 时逻辑相同，但计划员通常会在 MD04/STOCK 需求清单里先评审再转。手工 PR 则来自人的提报，需要走释放审批。

Q：PR 删除了，关联的 PO 会怎样？

A：PR 删除（或关闭行项目）不影响已创建的 PO，但未清 PR 行会被 MRP 再次考虑。规范做法是：不再需要的 PR 行做"关闭"（最终收货标识/删除标识），而不是物理删除。

实战经验

  • PR 的需求日期是供应链的指挥棒：MRP、采购员都盯着它。培训需求部门"按真实需要提日期"，集中把日期写成"明天"会导致采购满盘皆急。
  • 文本 PR（无物料编码）是主数据治理的漏洞：同样的东西每次描述都不同，价格、供应商无法分析。建议对高频文本采购物项推动建物料编码。
  • 释放策略设计宁可先简单后复杂：上线先用"按金额分级"跑顺，二期再加物料组、工厂等多维。第一版就上五维矩阵，测试和运维都会崩溃。
